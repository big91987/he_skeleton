# 公共交付产物契约

## 默认目录

```text
docs/delivery/
├── README.md
├── milestones/
│   └── M01-<outcome>.md
├── tasks/
│   └── T001-<outcome>.md
└── verification/
    └── M01-verification.md
```

项目已有等价目录或 Issue Tracker 时沿用既有事实源。不要为了使用本 Skill 复制一套平行状态。外部 Tracker 可以维护分配和通知，仓库仍应保存能够脱离工具完成交接的目标、契约、证据或稳定链接。需要 Excel 版本时，把它作为 Markdown 任务事实的导出或派生视图；若项目明确指定 Excel 为唯一可写事实源，则 Markdown 只保存稳定基线和链接，不同时手工改两套状态。

| ID | 结果 | 里程碑 | 负责人 | 状态 | 硬依赖 | 验证 |

总览是任务和验证记录的投影。详细结果只写在对应文件，避免复制。

## 状态更新规则

- 任务文件是任务状态事实源；总览只汇总。
- 状态改变、硬依赖改变、公共接口改变或出现阻塞时更新任务文件。
- `Done` 必须有验证证据和实施结果。
- `Blocked` 必须写清阻塞事实、影响和解除条件。
- `Dropped` 必须写清原因和替代位置。
- 里程碑 `Accepted` 必须有验证记录，不能只根据任务数量推断。

## 一个完整示例

阶段目标：为已有内部平台增加项目级 API 凭据能力。

```text
M01：项目管理员能够创建、撤销并审计应用凭据
  T001：冻结凭据创建、展示和撤销契约（SDD）
  T002：实现凭据元数据和密文存储（TDD，依赖 T001）
  T003：实现项目管理员管理接口（TDD，依赖 T001、T002）
  T004：实现管理页面与错误状态（TDD，软依赖 T003，可基于 Mock 并行）
  T005：完成端到端权限、撤销传播和审计验证（Validation，依赖 T003、T004）
```

这个切法保留了必要契约任务，但最终里程碑仍是端到端业务结果。执行者可以分别使用不同工具，所有任务共享相同的输入、接口和验收证据。
