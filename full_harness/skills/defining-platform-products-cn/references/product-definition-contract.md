# 平台产品需求基线与 G1 契约

## 广义 PRD 结构

### 1. 背景与问题

- 需求来源和业务背景；
- 目标用户的现状及替代方案；
- 问题频率、影响和证据；
- 为什么现在处理。

### 2. 产品目标

- 一句话产品判断；
- 当前阶段业务结果；
- 成功标准；
- 非目标。

### 3. 用户与运营模式

- 直接用户；
- 平台运营者；
- 上游能力提供者；
- 预算、风险和支持责任人；
- 申请、使用、支持和退出方式。

### 4. 产品级业务架构

- 端到端价值流；
- 角色与责任；
- 业务能力及边界；
- 核心业务对象；
- 生命周期和业务不变量；
- 正常、异常和人工介入流程。

### 5. 阶段范围

- 当前阶段用户和闭环；
- P0/P1 或等价优先级；
- 质量与规模边界；
- 明确后置；
- 下一阶段触发条件。

### 6. 需求与验收

- 功能需求；
- 产品级质量需求；
- 业务规则；
- User Story / Use Case；
- Acceptance Criteria；
- 验收责任和验证方式。

### 7. 依赖与治理

- 外部系统和组织依赖；
- 风险和假设；
- 需求来源及追踪；
- 已确认决策；
- 开放问题。

## G1 完整性检查

### 目标与证据

- [ ] 问题和目标不是由功能清单反推；
- [ ] 成功标准可以观察；
- [ ] 非目标足以阻止范围自然膨胀；
- [ ] 事实、假设和提案已区分。

### 用户与运营

- [ ] 直接用户及核心工作明确；
- [ ] 运营、容量、风险和支持责任明确；
- [ ] 当前运营模式明确；
- [ ] 用户获得和退出服务的方式明确。

### 业务架构

- [ ] 至少一条端到端价值流完整；
- [ ] 核心能力均有业务结果和责任人；
- [ ] 产品与相邻平台、底层执行系统、伙伴的边界明确；
- [ ] 核心业务对象、生命周期和不变量明确；
- [ ] 每个作为旅程前置条件的核心对象都有可追溯的来源和“首次可用”路径：创建或接入责任人、受支持操作方式、可用性核验、变更与退出；
- [ ] 关键异常和人工处理没有遗漏。

若对象被描述为“预配置、预置、外部提供或运维初始化”，必须把对应流程和责任写入运营模式或外部依赖。缺少正式 UI、API、CLI、声明式配置或经批准的人工操作规程时，此项不得勾选；数据库直改和一次性 migration 默认不算受支持入口。

### 阶段与需求

- [ ] 当前阶段是端到端切片；
- [ ] P0 需求都能追溯到目标和价值流；
- [ ] 业务规则不存在已知冲突；
- [ ] 产品级质量要求足以约束架构；
- [ ] 后置项和重新评估触发条件明确。

### 验收

- [ ] 每条 P0 需求都有可观察 AC；
- [ ] 核心失败场景有预期业务结果；
- [ ] 验收责任人和验证方式明确；
- [ ] 不使用“支持、完善、智能、生产级”等不可验证词替代标准。

### 架构就绪

- [ ] 没有未处理的方向性未知项；
- [ ] 外部依赖和硬约束明确；
- [ ] 需要 HLD 解决的问题已列出但未越界预决；
- [ ] 技术可行性风险已有证据、PoC 计划或明确假设。
