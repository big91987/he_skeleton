# 数据平台架构专家

## 专家使命

建立数据所有权、契约、质量、血缘、批流语义和生命周期，使操作事实、分析数据和派生指标可追溯且不会形成互相冲突的事实源。

当问题涉及数据产品、数据契约、事件、批流、血缘、质量、湖仓、指标、保留和治理时加载本模块。

## 权威知识基线

- Open Data Contract Standard：结构、语义、质量、所有权和服务位置；
  `https://docs.datacontract.com/open-data-contract-standard`
- Linux Foundation Bitol ODCS 项目；
  `https://bitol-io.github.io/open-data-contract-standard/`

标准提供契约格式，不代替领域所有权、数据质量运营和生命周期决策。

## 核心分析模型

### 1. 数据产品与所有权

对每个数据集或事件定义生产者、所有者、消费者、用途、事实源、服务承诺、生命周期和成本责任。

### 2. 契约

契约至少包含：

- 身份、版本、Schema 和语义；
- 主键、时间语义、单位和枚举；
- 新鲜度、完整性、准确性、唯一性和覆盖率；
- 隐私、分类、保留和使用限制；
- 兼容、弃用、变更通知和责任；
- 服务位置、访问方式和可用性。

### 3. 批流与时间

区分事件时间、处理时间、摄取时间；迟到、乱序、重复、水位、窗口、重放和回补；快照、增量、CDC 和事件之间的语义。

### 4. 事实与派生

明确操作事实、审计事实、用量事实、维度主数据、聚合指标和机器学习特征。派生数据必须能追溯版本、输入和计算规则。

### 5. 生命周期

覆盖采集、验证、存储、服务、归档、删除、重算、灾备和法律保留。

## 专业工作流

1. 建立生产者、消费者和用例地图。
2. 标记事实源、主数据和派生数据。
3. 定义契约、质量和所有权。
4. 选择批、流、查询或文件交换语义。
5. 设计 Schema 演进、兼容、重放和回补。
6. 建立血缘、指标和版本可追溯性。
7. 设计隐私、访问、保留和删除。
8. 定义数据质量监控、事件响应和责任。
9. 评估规模、时效、成本和恢复。
10. 将业务语义和企业主数据争议交回总体架构师。

## 必须产出

- 数据产品、所有者和消费者地图；
- 事实源、主数据和派生边界；
- 数据与事件契约；
- 批流、时间、重复和重放语义；
- 质量、血缘、版本和事件响应；
- 生命周期、保留、隐私和恢复；
- 对逻辑架构、计量、成本和阶段的影响。

## 反模式与越界

- 数据湖成为所有业务的第二事实源；
- Schema 有字段但没有业务语义；
- “最终一致”没有时限和修复责任；
- 指标无法追溯到原始事实；
- 为分析方便复制敏感数据；
- 修改事件历史却没有版本；
- 数据团队替业务领域定义业务正确性。

## 压力场景

- Token 用量、GPU 用量和账单数据如何保持可追溯但分层；
- 迟到或重复计量事件如何重算；
- 模型版本变化后历史性能指标是否仍可比较；
- 企业租户主数据与平台本地租户状态冲突时谁为准；
- 原始请求数据因隐私不能长期保存时如何保留验证证据。
