# 演进、迁移与选择权

## 变化向量

对每个可信变化记录：

| 字段 | 含义 |
|---|---|
| 触发条件 | 什么可观察事件会使变化成为现实需求 |
| 证据 | 当前信号，而非纯想象 |
| 稳定承诺 | 用户与运营者依赖的不变量 |
| 可变机制 | 可能改变的技术、拓扑、策略或流程 |
| 影响半径 | 受影响的用户、数据、运营和契约 |
| 切换成本 | 迁移、培训、停机、双轨和转换成本 |
| 最小接缝 | 能包住变化的最小接口 |
| 替换测试 | 如何证明替换或共存有效 |

常见变化包括运营模式、规模、负载、租户、环境、供应商、Runtime、法规、组织归属和单位经济性。

## 稳定内核与可变边缘

优先稳定：

- 用户与运营承诺；
- 领域术语、身份和标识；
- 责任归属与事实源；
- 用量事实和审计证据；
- 声明式意图和生命周期状态；
- 错误分类、关联、兼容与版本规则。

保持可替换：

- 供应商资源；
- 执行引擎和 Runtime；
- 部署拓扑；
- 调度与优化算法；
- 存储、消息、可观测和工作流实现；
- 从用量事实派生的价格策略。

稳定语义和演进规则，不要预先设计所有未来字段。

## 接缝测试

新增适配器、插件 API 或抽象前确认：

1. 是否已有或可信计划了两个实现；
2. 是否服务同一用户承诺；
3. 小接口能否隐藏差异而不成为能力并集；
4. 替换价值是否足以承担长期一致性成本；
5. 兼容性是否可独立测试。

多数答案为否时，只做内部封装。

## 阶段设计

每个阶段定义目标用户、运营模式、能力结果、质量与规模范围、进入证据、退出标准、明确延后项、可迁移资产和重新评估点。

优先使用触发式扩展：人工成为瓶颈、故障域过大、容量周期违反目标、出现第二实现、需要成本归属、外部租户或商业需求得到验证。

## 可逆性

| 类型 | 示例 | 处理方式 |
|---|---|---|
| 容易逆转 | UI、内部工具、可替换库 | 快速决定、度量、复盘 |
| 中等 | 网关、工作流、部署控制器 | 定义退出路径和迁移测试 |
| 困难 | 身份、租户边界、事实源、公开契约 | 研究替代、记录权衡、取得批准 |
| 累积性 | 重复账本、定制适配器、运维负担 | 评估长期维护与收敛路线 |
