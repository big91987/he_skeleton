# 架构决策台账与断点续传

## 适用范围

当架构工作包含多轮澄清、多个关联决策、会话中断、上下文压缩、多人交接或多个目标产物时使用。每个独立架构范围维护一个台账，项目事实只写入项目台账。

## 检查点

```markdown
# <架构范围>决策台账

> 状态：Active | Complete | Blocked
> 目标产物：<路径或标识>
> 更新：<时间>

| 字段 | 值 |
|---|---|
| 当前架构层级 | 0～5 |
| 最近完成轮次 | ... |
| 活动轮次 | ... 或 none |
| 活动问题 ID | ... |
| 未回答 ID | ... |
| 下一个 ID | A-001 |
| 恢复说明 | ... |
```

## 决策记录

每项必须保存：

| 字段 | 含义 |
|---|---|
| ID | 稳定、唯一、永不复用 |
| architecture_layer | 目标、运营、能力、逻辑、部署或实现 |
| semantic_key | 用于语义去重的稳定含义 |
| decision_type | `Fact`, `Validation`, `Decision` |
| question | 向用户展示的原始问题 |
| options | 原始互斥选项 |
| recommendation | 推荐方案、理由和成立条件 |
| architecture_impact | 对整体架构、阶段和下游的影响 |
| user_answer | 用户原始回答或修正 |
| conclusion | 归一化后的当前契约 |
| status | `Proposed`, `Asked`, `Accepted`, `Rejected`, `Conflict`, `Superseded`, `Blocked`, `Frozen` |
| prerequisites | 必须先确定的决策 ID |
| descendants | 当前决策变化时受影响的 ID |
| evidence | 事实、来源、证据等级和日期 |
| source_coverage | 需求能力、事实源、既有架构表格和图的覆盖结果 |
| validation | 验证方式与退出条件 |
| artifact_mapping | 消费该结论的目标章节 |
| supersedes | 被替代的决策 ID |

## 决策前沿

```text
完整读取并校验台账
→ 读取目标产物、需求基线和新证据
→ 建立能力—事实—责任清单并核对既有表格与图
→ 恢复活动轮次的未回答 ID
→ 否则计算所有前置已解决的未决节点
→ 删除已接受决策的语义重复项
→ 调查事实问题并登记证据
→ 选一个基础决策或 3～7 个独立决策
→ 分配 ID，以 Asked 状态保存并回读
→ 展示已保存的准确问题
→ 映射回答、保存、回读并重新计算
```

用户回答“全部按推荐”“都是 A”或“除 A-014 外其余选 A”时，只有映射无歧义才能批量接受。“继续”不代表接受。

## 来源优先级

1. 用户或正式决策人的最新明确回答；
2. 后续已接受且替代旧结论的决策；
3. 已接受的项目决策记录；
4. 已批准的目标产物；
5. 已验证的技术证据；
6. 研究资料；
7. 提案和推荐。

目标产物落后于台账是同步缺口，不是重开已接受决策的理由。

## 不变量

- 每个已展示问题已经存在于活动轮次检查点；
- 领域、模块、依赖或拓扑清单型问题具有完整 `source_coverage`，每个源项均已纳入、明确合并或显式排除；
- 同一架构概念在责任表、流程、事实源表和架构图之间没有未解释的数量或归属差异；
- 每个未回答活动问题状态为 `Asked`；
- 批内不存在前置与下游关系；
- `Accepted` 节点不进入待询问前沿；
- `Frozen` 节点指出发生变化的前置条件；
- `Superseded` 节点指出替代者；
- 每个完成轮次都有成功的写入和回读记录；
- 每个进入目标架构的结论都能映射到 `Accepted` 决策或已批准需求基线。
