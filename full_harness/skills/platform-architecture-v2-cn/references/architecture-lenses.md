# 架构分析视角

只使用可能改变架构方向的视角。

## 目标与运营

| 视角 | 关键问题 |
|---|---|
| 结果 | 平台让什么业务或运营结果可重复发生？ |
| 用户 | 谁消费平台，谁获得下游价值？ |
| 运营 | 谁负责容量、策略、支持、升级和事件？ |
| 模式 | 内部共享、成本分摊、托管服务、商业产品、伙伴交付还是组合？ |
| 控制权 | 哪些是战略控制点，哪些可以委托？ |
| 成功 | 什么可观察结果表示当前阶段完成？ |
| 非目标 | 哪些相邻问题明确排除？ |

## 能力与领域

对每项能力记录：

- 用户或运营结果；
- 核心对象或策略；
- 所属领域和生命周期负责人；
- 事实源；
- 相邻领域与交换意图；
- 被委托的执行机制。

术语、状态、操作者、扩缩方式或故障处理不同通常意味着不同领域。体验需要一致时统一入口和共享主数据，不要因此合并领域逻辑。

## 流程

| 流程 | 揭示内容 |
|---|---|
| 用户或价值流 | 是否完成一整项用户或运营工作 |
| 数据或请求流 | 时延、吞吐、协议和数据归属 |
| 控制与调和流 | 期望状态、策略、异步完成和一致性恢复 |
| 计量与成本流 | 用量事实、归属、聚合、定价和结算分离 |
| 遥测与事件流 | 信号、关联、告警、诊断和恢复责任 |
| 治理与审计流 | 身份、审批、策略判断和证据留存 |

对每条流程确认发起者、事实源、同步路径、异步工作、失败响应、幂等边界和关联标识。

## 质量属性

用场景和指标表达：

- 性能：负载形态、并发、吞吐、时延分布、突发和数据量；
- 容量：基线、增长触发、饱和信号和供应周期；
- 可用性：用户可见服务、目标窗口、依赖和允许降级；
- 恢复：故障范围、发现时间、RTO、RPO 和重建机制；
- 隔离：租户、团队、工作负载、秘密和噪声邻居；
- 安全：身份、信任区、特权路径、审计和供应链；
- 可运营：值班、诊断、变更、回滚和升级版本差；
- 经济性：成本驱动、归属单位、利用率、人力和许可；
- 可迁移：可能迁移、受保护资产、专有表面和退出测试。

## 故障与责任

考虑控制面不可用、下游完成状态丢失、局部故障、计量重复或延迟、身份与策略服务失败、版本不兼容、容量耗尽、操作失误和不安全自动化。

分别指定发现、隔离、降级、恢复、调和和沟通责任。
