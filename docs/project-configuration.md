# 项目决定产品形式

Issue 模板不选择或限制产品类型。任务可以是需求文档、CLI、服务端、SDK、桌面程序、网页或其他项目内容。执行工作区导入完整仓库的普通文件，包括 AGENTS.md、docs、代码和构建声明，不再只导入 app/。

通用 Agent 指令要求遵循用户目标与已有项目决策；缺少运行环境时提出具体问题，不改造成静态网页来过检查。没有自动验证器时，提交代码和文档到任务分支，并明确标记 needs_verification，不发布虚假的网页或绿色验收。

## 项目自选验证

配置文件为项目自己的 harness-project.json；不会被同步脚本覆盖。配置从触发工作流的固定源码快照读取，不接受 Agent 修改后即时生效。

仅当项目选择静态浏览器验证时，配置：

```json
{
  "instructions": "遵循项目自己的需求和技术约束。",
  "verification": {"kind": "static-browser", "root": "app"}
}
```

其中 root 是项目内相对目录，不固定为 app。此适配器需要 index.html 和 acceptance.json，并生成截图与浏览器报告。这些条件只属于该适配器，不属于所有项目的入口条件。

不配置 verification 时，可以澄清或开发任意类型的项目，但自动验收状态为待验证。当前只有 static-browser 验证适配器已经实现；任意 shell 命令、后端环境编排、GPU 测试和桌面程序验证未自动接通。配置未知验证器会明确拒绝，不会自动改成网页。

## 边界

- 控制文件 harness/、.github/、harness-project.json、harness-upstream.json 可以被读取，但任务不能修改后自行取得执行权限；应走单独审查的基础设施变更。
- 当前只支持普通文件，拒绝符号链接和潜在凭据文件；忽略 .git、node_modules、虚拟环境和缓存。单文件 2 MB、2000 文件/50 MB 总量为当前执行限制，不代表产品类型限制。
- 不自动安装依赖或操作外部服务。需要这些能力时按任务授权与环境实际能力处理，不能谎报构建/验证成功。
- 原 app-only Session 不能直接当完整仓库继续使用；旧结果可以重新发布，新开发任务须建立新的完整工作区，避免覆盖遗留状态。
- 完整阶段工作流、Issue 测试分支路由和生产级恢复治理仍是独立未完成项。
