# 测试维护清单

这套测试保护工具箱的执行规则，不是产品验收报告。测试数量不是质量指标；优先维护少量能穿过真实调用链、能抓住具体故障的场景。

## 当前测试集

本次治理将离线测试方法从 142 个减到 121 个，文件从 17 个减到 13 个。随后补充折叠进度发送恢复和超长累计内容保真测试，当前共 125 个。下表的数量是 unittest 测试方法数，不是独立业务需求数或真实 Agent 执行次数；合并后保留的场景仍然执行。`subTest` 不另算一个方法。

|---|---|---:|---|
| `test_light.py` | 当前轻量流程：持久化、同 Session 接续、文档确认、原生研发 Hook、结果与评论 | 21 → 18 | 五个零散状态测试换成入口到评论的连续场景；错误回复不污染状态并入原始结果展示测试 |

## 这次重点更新了什么

- 轻量流程的连续场景现在通过 `light.main()` 接收 Issue 事件，实际初始化工作区、每轮从磁盘恢复状态、生成文档和回复；只模拟 GitHub 和 Codex 外部接口。覆盖问答不推进、重看文档不刷新确认时间、确认后推进、同 Session、阶段内一次调用、确认后自动接下一 Job、重复事件不重复执行或发评论；过程消息在同一折叠评论内更新，最终回复另发，工具内容不转发；展示完整外层消息及结束/失败事件，进程退出后收口执行状态，不把 item.completed 当整轮结束。
- 原“文档评审失败要求修复”测试直接调用了需求阶段 Stop Hook，但真实工作流已不在需求/设计调用它，删除该脱节场景；保留需求/设计不运行研发检查、研发失败后修复再检查的真实调用链测试。
- 原“开发依次调用四个步骤”测试把四个步骤全替换成改变状态的假函数，主要在重述循环实现，删除。
- 原“独立评审退回设计后自动走完”测试用假作者绕开了设计重新确认，删除。保留设计修订必须再审批的场景。
- 自然语言处理测试改名为“消费 approve/continue_stage 结果”。它们喂的是固定模型输出，不能证明模型会把“继续”理解正确。
- 真实完整流程探针 `integration_full.py` 以前提前停住也能退出成功，现在只有达到已验证的 delivery 才返回成功。
- CI 功能分支只由 PR 触发；主线 `main`、`codex/full-development-workflow` 合入后运行 push 检查，避免同一功能分支 push/PR 两份重复任务。完整回归约数秒，暂不再引入按变更文件挑选测试的框架。

## 怎么运行

安装 `requirements-dev.txt` 中固定版本的依赖后，在仓库根目录执行：

```sh
# 当前轻量协议、回复及校验链；开发时可先跑这一组
python3 -m unittest discover -s tests -p 'test_light.py' -b

# 发布前及 CI：所有仍支持模板与共用模块的离线回归
python3 -m unittest discover -s tests -p 'test_*.py' -b
ruff format --check .
ruff check .
```

`-b` 在成功时收起夹具输出，失败时保留相关日志。`test_native_skills.py` 中一个原生目录测试需要本机 Codex CLI；未安装时会明确显示 skipped。它检查原生目录配置，不发送模型请求，其余离线测试不依赖模型服务。CI 没有安装 Codex 时，应报告 120 通过、1 跳过，而非笼统宣称 121 项全部通过。

以下三个脚本在默认发现范围之外，必须显式加 `--run-live`，会消耗模型额度：

| 手工探针 | 范围与限制 |
|---|---|
| `integration_skills.py` | 原生渐进式披露、切换 Skill 范围、同 Session 记忆；使用合成任务 |
| `integration_stop.py` | 原生 Stop Hook 拒绝过早完成并在同一次执行内修复；使用合成文件检查 |
| `integration_full.py` | 完整模板的 CLI 项目、分阶段人工确认夹具、校验与独立评审；不覆盖轻量模板的真实自然语言判断 |

```sh
python3 tests/integration_skills.py --run-live
python3 tests/integration_stop.py --run-live
python3 tests/integration_full.py --run-live
```

这次没有重新运行上述模型探针，也没有把修改探针退出码说成完整流程已验收。轻量流程在真实 Issue 上的自然语言解释、Skills 是否实际执行、界面可用性，仍需查看对应运行证据。尤其 full → light 跨模板接续不同于轻量协议升级的 `migrate()`，本测试集不证明它已支持；跨模板状态接续仍是已知缺口。

## 后续增删规则

1. 先说清要拦住的具体错误和应观察的结果；没有独立风险就扩展已有场景，不按代码分支数机械加测试。
2. 不为可逆的低影响改动强制新增测试，不锁定提示词整句、内部函数顺序或无用户意义的实现结构。
3. 可在 GitHub、Codex 等外部接口使用夹具，但不能把审批、状态读取、校验和发布全部 mock 后称为端到端通过。
4. 状态和恢复优先经过真实入口及磁盘读取；权限、文件逃逸、重复事件、陈旧确认、错误交付等保护不能只为减数目而删除。
5. 报告说明验证范围和未验证项。方法数量、离线回归、原生模型探针、实际产品验收分别表述。

本次在临时副本分别注入“丢失 Session”“不保存下一阶段”“重看文档刷新时间”“重复事件再次调用”四种故障，新连续场景均能检出；临时注入未进入产品代码或常驻测试工具。

阶段产物约定：安装回归覆盖已有 Owner AGENTS.md 保留与首次注入产物约定；轻量接续回归检查需求/设计提示词不携带旧单文件 artifact 暗示。模型是否真正遵循 Skill 并生成可审查原型、架构和契约，须另看真实运行及实际文件，单元回归不证明这一点。

累计进展回归核对整轮原始事件、同 ID 消息不覆盖、超长内容分段后可无损重建 JSON，并保留中断发布恢复检查；真实日志回放用于核对旧评论回填。

同次运行接续：将原跨多次运行的轻量连续场景更新为一个 run_id 下三个独立 Job 的七次调用，实际读写状态并验证 Session、确认时间和跨 Job 输入保持，已完成 Job 重试不重复调用；新增一个集中收件场景覆盖评论分页、权限、机器人过滤、去重、游标落盘、关闭与超时。GitHub/Codex 为外部接口夹具，真实同次 Actions 接续需另看实验 Issue。

等待网络回归：在真实 api() 与等待循环之间只替换 gh 子进程返回，分别注入 EOF、超时、权限查询 503；验证恢复后同一评论只消费一次、落盘内容未丢失，同时 403 明确失败且写请求不自动重放。该测试不证明宿主机网络或 GitHub 产物服务始终可用。
